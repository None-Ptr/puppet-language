# OpenPuppet · v2 设计草案（待评审）

> **状态**：草案，**未冻结**。

> **边界**：本文件只记录"决定"与"待决"，不含任何本机路径或实现细节。

## 0. 命名与仓库拓扑

| 名称 | 角色 | 形态 |
|---|---|---|
| **OpenPuppet** | 项目总称 | 不是代码实体 |
| **puppet** | 设计 + 语言标准实现 | 本仓。目录名 / import 名 / CLI 名均为 `puppet`；**PyPI 发行名另取**（`puppet` 已被 Puppet Inc. 占用，发行名与 import 名分离） |
| **puppethub** | 软件 | 第二仓。app 的搭建 / 运行 / 运行时定制 / 融合 |
| **puppetOS** | 系统融合 | 基于 Linux 内核的发行版。**仅设计文档，本项目不实现** |

- **依赖方向**：`puppethub` → `puppet`，单向。正式依赖走 PyPI 版本约束（如 `>=0.1,<0.2`），开发期用本地可编辑安装覆盖。
- **conformance 用例随 `puppet` 发行包分发**；`puppethub` 的 CI 必须拿它自证合规（这是拦截跨仓漂移的唯一机制）。
- 旧实现仓库**归档**，其结论作为本草案"表态"的输入（见附录 A）。
- **两个仓，不是三个**：`puppetOS` 没有代码仓。

## 1. 定位（不变的部分）

- **北极星**：**An app is an agent.** app 本身就是会感知、决策、行动、记忆、调用工具的 agent。
- **首要用户** = 人类操作者/所有者；LLM = 共作者（写 `.puppet` 与能力代码）。
- **对话是驱动手段，不是 app 的形态**：造出的 app 窗口不含聊天框。
- **第一原则：杜绝静默失败。** 任何"降级 / 丢弃 / 无效"都必须产生诊断、日志或事件。判断标准：这条路径失败时，agent 能看到吗？看不到就是缺陷。

---

## 2. 三层职责与边界

- **puppet（标准）**：语法 + IR + **确定性执行语义** + **UI 词汇语义** + **渲染契约**。**不含任何具体渲染实现**。
- **puppethub（软件）**：**单 app 运行器**。搭建 / 运行 / 运行时定制 / 融合（融合 = 设计期合并）。
- **puppetOS（发行版设计）**：多 app 编排，分三层——底座（生命周期：启停 / 休眠 / 唤醒 / 升级 / 落盘）、核心（跨 app 观察与编排）、顶层（**可选**兼任各 app 的大脑，默认不兼任）。
- **判据**：凡问"`puppethub` 该不该实现 X"，就问"**这是不是软件该干的事**"。
- **本期没有任何多 app 代码**：多 app 编排 100% 属于设计，可行性待未来验证。

---

## 3. 标准的边界与严格度

- **渲染契约必须写成"可观察行为"**——用户看到什么、什么事件在什么条件下触发、布局遵循什么规则。**禁止**写成"某后端控件的映射表"（否则契约会被第一个实现反向绑架，标准沦为实现的副产品）。
- **严格度**：独立版本号（改语义即升版）+ 一份**人读规范** + 一套**可执行 conformance**。
- **实现零第三方依赖**：第三方必须能无门槛地安装并运行 conformance。
- **跨 app 不进语言**：app = 独立真源 + 独立运行单元；**单个真源自足**，可被单独拷走、交付、存活。跨 app 只在**调度层**发生，不在语言层。

## 4. 语言 v2

### 4.1 保留（v1 结论，确认沿用）

- 扁平逐行命令；**显式节点 ID**，撞名立即报错。
- **相对寻址**：`before` / `after` 锚点，不用数字索引。
- **7 个集合原语**（追加 / 删除首个 / 条件删除 / 条件更新 / 清空 / 排序 / 计数）。
- **L3 表达式边界**：算术 / 比较 / 逻辑；白名单隐式转换（数字+字符串拼接、`bool` 转文本、颜色转字符串），其余类型混用**报错**不猜；**禁止**循环、自定义函数、if/else。
- **错误模型**：批内**部分应用** + 收集**全部**错误 + 精确行号；`upsert` 幂等。

### 4.2 改动（相对 v1）

1. **引入受限活绑定**：值类属性可直接写表达式，渲染期持续求值，依赖由引用自动推导；**结构变更仍走命令**。v1 的"`add` 静态字面量 / `set` 求值"分裂语义**作废**。
2. **程序与状态分家**：`app.puppet` 只放**程序**（声明，人/LLM 写）；**状态**（数据项、运行期值）单独一份，**引擎只写状态、绝不改写程序**。反向序列化成为纯程序操作（幂等、可 diff）。
3. **`template` 升格为一等节点类型**：有 ID、住节点表、有 `children`；列表通过 `template=#tpl` 绑定。v1 里"模板子节点住在模板对象里"的结构特例随之消失。
4. **状态字段升为节点运行期属性**：`hover` / `focus` / `pressed` / `error` 与 `visible` / `disabled` / `ink` 等**并入同一状态模型**；**可被 `set` 写、可被绑定读**（如 `#b.error`）；外观映射交给渲染器。→ 错误态才可能被真正驱动，而不是永久亮着。
5. **动画与图标按语义定义**：可动画属性按**语义**定义（值 / 位置 / 尺寸 / 透明度 / 颜色），渲染器做不到就**明确降级**，不得从标准里删除；图标定**语义名 + 必须支持的核心子集**，渲染器可扩展，缺失必须报"未实现"而非静默空白。
6. **控件清单按语义定死**：先按语义定清单（含标签页等），渲染器各自实现或明确降级。**不得**因为某个后端用不了就从标准里删控件。
7. **`count()` 升格为普通函数**，并**扩充内置函数集**（活绑定会让值表达式大量使用；v1 的函数集过薄）。
8. **`dropdown` 的选中值改名 `selected`**，释放 `value`，让全部控件共享同一套 `value` 语义。
9. **`listen` 取消"双模式降级"**：不再有"某种模式下无消费者 → 降级 + 警告"的规则。
10. **`revision` 语义收窄为 per-app**：每个 app 实例一条序列，唯一用途是让外部驱动者在断线重连后判断是否漏事件。

### 4.3 活绑定带来的规范义务（必须逐条写清）

- **依赖图与求值时机**（何时重算、以什么顺序）。
- **收敛性**：循环依赖必须在**编译/校验期**诊断为错误；运行期**禁止**"跑满 N 层就静默放弃"这类截断。
- **求值失败必须可见**（不得渲染成空白或旧值）。
- **模板行内的绑定按行实例化求值**。
- **`set` 与绑定的优先级**：必须写进规范，不得留给实现决定。

## 5. 运行与宿主

- **运行时可选**：带 LLM / 不带 LLM（一个开关；**不是两条构建路径**）。
- **产物**：**一套形态 + 开关**。不再有"两种 build"。
- **单写者下移为 per-app**（每个 app 实例一个写者）。
- 单实例生命周期可控；**接口必须容许外部无 GUI 驱动**（这是 `puppethub` 对 `puppetOS` 的唯一义务）。
- **参考渲染器暂不定**：先定标准与语言，渲染器后选（遵从第 3 节的契约纪律）。
- **自检归驱动者**：`puppethub` 只保证"能观察"（能产出截图 / 状态 / 事件）；是否拿它自检由驱动方决定，能力不随模式出现或消失。
- **插件只保留观察类与扩能类钩子**：**禁止改写命令流**（否则同一 `.puppet` 在不同插件环境下语义不同，标准失效）。
- **安全不在范围内**：不做沙箱、标准不做承诺。（但"缺失 / 失败 / 超时 / 异常必须可见"是不可让步的**功能性**要求。）

---

## 6. 能力层（工具）

- **保留**：能力装饰器与独立能力文件；从签名与类型提示自动提取契约；**docstring 非空强制**；`async` 函数直接 await、同步函数走线程池；返回值强制可序列化 + 符合声明结构；按槽丢弃陈旧结果。
- **槽是唯一的异步观察面**，且**必须支持超时与取消**：只有"进行中 / 成功 / 失败"三态是不够的——**挂死的能力会变成永久"进行中"，等于 agent 瞎了**。超时必须产生可见观察。
- **槽值可直接绑定读**：三段式的"某事件发生时去改某处文本"退化为过渡手段，不是唯一写法。
- **依赖声明**：**显式声明 + 扫描兜底 + 不一致必须报警**。仅靠扫描源码中的 import 是启发式的，动态导入 / 条件导入会被静默漏掉，直到部署机上才缺包。

---

## 7. 持久化与观察

- **程序与状态分家**（见 4.2）：引擎只写状态文件，**绝不改写程序**。
- **状态文件原子写**（临时文件 + 原子替换）；状态分**持久分区**（跨重启存活）与**瞬态分区**（进程内、可丢）。半截写入 = 状态损坏 = 静默失败。
- **结构漂移**：**不自动迁移**，但**不许静默丢数据**——旧字段原样保留 + 显式诊断。
- **真源写回在批末一次性完成**：不允许留下"半批程序"。
- **观察流不得静默丢弃**：v1 在队列满时直接丢事件，这与第一原则冲突；v2 必须背压、断连声明或显式标记"事件丢失"。

---

## 8. 工程与流程

- **两个独立仓库**；跨仓依赖见第 0 节。
- **CLI 各归其位**：`puppet` = 标准工具（`spec` / `validate` / `conformance`，**不需要 app 即可运行**）；`puppethub` = 软件命令（`run` / `new` / `build` / `host` / `skills`，**必须作用在一个 app 上**）。
- **文档生成拆分**：**语言文档**由 `puppet` 生成（它属标准）；**宿主手册**由 `puppethub` 生成（它必须写平台事实：端口、凭据、能力清单、后端能力）。
- **流程**：**规范先行**。规范说不清的地方，用**一次性原型**定夺语义——原型**不进仓库、不当验收**；conformance 用例**从规范写**，不移植旧测试。

## 11. 渲染 / 几何 conformance（grill 决议）

围绕"渲染这块怎么自证合规"的一次 grill，6 条决议（已落入 `spec/05`、`spec/06`、`conformance/`）：

1. **几何可选 + 关系型断言 + 截图兜底**：几何是**可选**观测能力；一旦提供，用**定性 / 相对关系**
   断言布局（不比绝对坐标，跨渲染器可比）。截图是**兜底**（供驱动者自检），**不进机器断言**。
2. **一个协议**：conformance 实现协议即控制协议，`puppethub` 复用、不另造。几何 = `observe` 的
   **可选字段**；截图 = **可选请求**（只给驱动者）；实现启动时以 `hello` 握手**声明能力集**。
   "可无 GUI 驱动"这条义务只在协议里兑现一次（`headless`）。
3. **声明即 oracle**：conformance 把能力声明当 oracle——声明支持 → 验证行为；未声明 → 验证它
   确实发了 `DEGRADED_FEATURE`（非静默）；谎报支持却被用例抓出 → 不符。标准约束力不降。
4. **关系断言写在外部用例规格**（`expect.relations`），被测程序只长成真实 app；期望与实现分离，
   断言可审阅、可维护。
5. **关系词汇**：方位 / 包含 / 重叠 / 对齐 / 间距 / 比例，全部带容差（`tol` 缺省 1px，比例 0.05）；
   坐标系 = 窗口内容区左上角、浮点像素。
6. **确定性验证**：没有真实渲染器也能测关系——`load.renderGeometry` **观测面测试替身**
   （与业务能力替身 `capabilities` 同构：一个替业务能力，一个替观测能力）。

落地：`conformance/runner.py`（`hello` 握手 / `geometry` 观察 / 关系评估 / oracle）、
`conformance/cases/render.json`、`puppet/adapter.py` + `puppet/engine.py`（参考实现）、
`puppet/diag.py`（`DEGRADED_FEATURE.feature`）。
