# 02 · 中间表示（IR）

## 1. 两本账

本规范把"应用"拆成两份**互不混存**的数据：

| | **程序 IR** | **状态 IR** |
|---|---|---|
| 内容 | 声明：节点、结构、数据源结构、处理器、订阅 | 事实：数据项、运行期状态、槽、修订号 |
| 来源 | 由 `.puppet` 文本产生，**只由命令批次改变** | 由引擎在运行期产生 |
| 写回 | 批次结束时一次性写回 `.puppet` | 原子写回状态文件 |
| 是否可丢 | 否（它是只有一份的真源） | **是**（缺失时从声明默认值重建，不报错） |

**不变式**：引擎**绝不**用运行期产生的内容改写程序 IR。反向序列化只读程序 IR。

## 2. 程序 IR

### 2.1 节点树

每个节点：地址（唯一）、类型、父地址、子序（有序表）、属性表。

- 属性值以**规范源文本**存储：表达式**原样保留**，不求值。这样程序可以被逐行读、diff、再编辑。
- 模板是普通节点（类型为 `template`），带一个**绑定名**（`as` 声明的名字）。模板的子节点是普通子节点。
- 根节点是约定的内置节点，所有窗口挂在它下面。

**结构不变式**（违反即错误）：

1. 地址全局唯一（`ID_DUP`）。
2. 除根外，每个节点**恰好**有一个父（`PARENT_MISSING`）。
3. 父子关系无环（`MOVE_CYCLE`）。
4. 属性名必须属于该类型的词汇表（`UNKNOWN_ATTR`，警告级）。

### 2.2 数据源声明

每个数据源：地址、`persist` 标志、结构（字段名 → 类型 → 默认值表达式）、初始值表达式。

**数据源声明属于程序**；它的**数据项属于状态**（见第 3 节）。

### 2.3 处理器与订阅

- **处理器**：目标、事件名、绑定名、`when` 守卫、动作序列。
- **订阅**：目标、事件名。
- 两者都是程序的一部分；它们**不随状态变化**。

### 2.4 元信息

- 规范版本（程序声明其面向的规范版本）。
- 批次外独立调用的记录（若实现允许）。
- 实现**可以**附加自有元信息，但**禁止**将其用于改变本规范定义的语义。

## 3. 状态 IR

- **数据项**：每个数据源 → 行列表（有序）。
- **节点运行期状态**：
  - 状态标志：`hover` / `focus` / `pressed` / `error` / `visible` / `disabled`；
  - 交互产生的值：输入内容、选中项、开关状态、滑块位置等。
- **槽**：状态（进行中 / 成功 / 失败 / 超时 / 取消）、值、序号、时间戳。
- **修订号**：每个 app 实例一条序列，每批命令递增。用途只有一个：让驱动者在断线重连后判断是否漏了事件。

**状态可丢**：状态文件缺失、损坏或结构漂移时，实现必须能从程序 IR 的默认值重建应用，并且**不得**因此拒绝启动。

## 4. 绑定图

- 程序 IR 中每个**值类属性**，若其值不是字面量而是表达式，则产生一条**绑定**：`(节点, 属性) → 引用集合`。
- 引用来源有二：地址属性引用（`#id.prop`）与模板行绑定字段（`t.field`）。
- **绑定图必须是有向无环图**。出现环 → **错误** `BIND_CYCLE`，在编译/校验期报告，带精确行号。
- 引用不存在的地址或字段 → **错误** `BIND_UNKNOWN_REF`。
- 求值过程中的类型不符、函数错误 → 运行期诊断 `BIND_EVAL`。

**绑定图是静态可分析的**：它只由程序决定，不受状态影响。这是"传播可证明收敛"的依据（见 `03-semantics.md` 第 2 节）。

## 5. 序列化与写回

- **程序写回**：从程序 IR 反向生成 `.puppet` 文本；**在批次结束时一次性完成**，不允许留下"半批程序"。
- **状态写回**：**原子替换**（写临时文件后重命名）。半截写入视为缺陷。
- **结构漂移**：状态文件中出现程序里不存在的字段 → **不自动迁移**，**不删除数据**，产生显式诊断（`PERSIST_SCHEMA_DRIFT`）。
- 反向序列化的输出**应该**与输入文本在语义上等价，且**应该**保持人类可读、可 diff。
