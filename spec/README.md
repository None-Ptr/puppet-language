# Puppet 语言规范

- **规范版本**：`2.1`（`2.0` 已冻结；`2.1` 起为**兼容修订**，逐条见 `06-diagnostics.md` 第 5 节）
- **状态**：`2.0` **已冻结**。冻结后任何条款都不得再改；改动语义**必须**升版本（见下），
  并在 `06-diagnostics.md` 的变更记录中登记。冻结意味着：既有 `.puppet` 程序的行为
  由本规范定义，实现不得反向影响它。
- **本目录的性质**：语言标准的人读规范，**不是**实现文档。`puppet` 包的实现必须符合本规范；**conformance 用例从本规范编写**，不从实现反推。
- **上层文件**：`docs/design-v2-draft.md`（设计草案）决定"为什么"；本目录决定"是什么"。

## 规范用语

| 用语 | 含义 |
|---|---|
| **必须** / **禁止** | 实现必须满足；违反即不符合本规范 |
| **应该** | 强烈建议；允许有理由的偏离，但必须产生可见诊断 |
| **可以** | 可选 |
| **未定义** | 本规范不作规定；实现可以自行选择，但**不得静默**——必须给出可见诊断或明确降级说明 |

**贯穿全规范的一条总则**：任何"降级、丢弃、无效、未实现"都**必须**产生可见的诊断、日志或事件。静默失败视为规范违反。

## 版本与兼容承诺

- 规范有**独立版本号**，与实现版本解耦。
- **改动语义即升版本**：任何使既有 `.puppet` 程序行为改变的改动，必须提升次版本或主版本，并在 `06-diagnostics.md` 的变更记录中登记。
- **新增可选属性/控件**属兼容改动，可以只提升修订号。
- 实现必须声明自己符合的规范版本；**行为与本规范不符时，以本规范为准**。

## 已确认的"派生决定"

规范必须把设计草案里未落到语法层面的地方定下来。以下条款都是**从已定决定推导出来的**，
已在正文标出，并经实现与 conformance 用例坐实；用户已逐条确认。**2.0 冻结时无未决项。**

1. **`template` 从动词降为节点类型**：既然模板升格为一等节点（住节点表、有子节点），它就应该用 `add` 声明。因此动词总数由 13 降为 12。
2. **状态外观收敛为单个 `states=` 属性**：既然状态标志（可读可写的运行期属性）与"状态下的外观"是两种东西，就应该分开。`states={hover: {bgcolor: #1d4ed8}}` 取代逐状态的字符串字段。
3. **`set` 作用于已绑定属性时，解除绑定并写入字面量**，同时**必须**产生一条诊断（不得静默地"设置无效"）。
4. **注释记号为 `//`**（不再与地址记号 `#` 共用）：`//` 到行尾为注释，`#` 只作地址/颜色。由此
   `#bad` / `#dad` 这类短地址不再有被误判为颜色的风险。
5. **颜色字面量与地址记号的消歧**：`#` 后接 **6 或 8 位**十六进制 = 颜色；`#` 后接其他标识符 = 地址。**不采用 3 位简写**——`#bad` / `#dad` / `#abc` / `#fed` 这类短地址会被误判成颜色（此问题由 conformance 用例暴露）。
6. **动作可直接作顶层语句**：集合原语既可作为 `on` 之下的动作，也可作为独立语句由驱动者直接下发（见 `01-grammar.md` 第 7 节）。
7. **行内事件必须携带行上下文**：派发者需给出行序号，引擎把模板的绑定名指向该行（见 `01-grammar.md` 第 8.1 节）。无法确定即报错 `ROW_CONTEXT`。
8. **`window` 的子节点按纵向流动**：窗口子节点的排布语义与 `col` 一致（主轴纵向，`gap` / `justify` / `align` 同样适用），渲染器不必为 window 另造布局规则（由两个参考渲染器的实现反推，见 `05-render-contract.md` 第 2 节）。
9. **绑定表达式不设额外白名单**：**任何值类属性都可以写表达式**（构成活绑定）；引用类属性一律禁止（`REF_ATTR_EXPR`）。属性归属哪一类由 `04-vocabulary.md` 标注，未标注者默认为值类。
10. **探针"无人消费"不产生编译期警告**：探针是**只读查询**，不改变程序或状态，因此没有"无人消费"造成的失败。编译期也无从知道有没有驱动者连接——"有没有人看"由**宿主**在运行时判断（见 `01-grammar.md` 第 7.10 节）。

## 2.1 之后如何提新议题

冻结**不是**终点，而是换了一种提要求的方式：

- 新增可选属性 / 控件 / 事件 / 图标 / 内置函数 / 诊断码 → **兼容改动**，提升修订号（`2.1`）。
- 任何使既有程序行为改变的改动 → 提升次版本或主版本，并在变更记录中登记。
- 想让某个语义**变得可选或可替换**（例如渲染器可选择不提供几何）→ 属"能力声明 + 可见降级"的范畴，
  由 `05-render-contract.md` 第 1 节的机制承载，**不需要**改语言语义。
