# 06 · 诊断与错误模型

## 1. 诊断的形状

每条诊断**必须**包含：

| 字段 | 说明 |
|---|---|
| 码 | 稳定标识符（本文件第 4 节的表），机读用 |
| 级别 | 错误 / 警告 / 信息 |
| 消息 | 人读说明，讲"发生了什么" |
| 位置 | **编译期诊断必须**有行号，**应该**有列号；运行期诊断必须有可追溯来源 |
| 建议 | 可选，讲"是不是想写…"，用于可猜错的场合（属性名、图标名） |

诊断**必须**同时具备机读形式与文本形式。

## 2. 级别语义

| 级别 | 含义 |
|---|---|
| **错误** | 该语句**未应用**（编译期），或该运行期操作**失败**。**不中断本批**其余语句。 |
| **警告** | 已应用，但语义可疑或很可能不是本意。 |
| **信息** | 正常但驱动者值得知道：降级发生、陈旧结果被丢弃、事件丢失、状态被重建。 |

## 3. 三条不可让步

1. **精确位置**：编译期诊断必须带行号（**应该**带列号）。没有位置的诊断视为不合格。
2. **部分应用 + 全量收集**：一条语句失败不阻断后续；批结束时**必须**给出全部诊断的汇总。
3. **没有静默**：任何"降级 / 丢弃 / 未实现 / 上限触发 / 重建"**必须**至少产生一条信息级诊断或一条观察事件。**禁止**静默截断、静默丢弃、静默空白。

**诊断的作用域是"一步"**（一次 `load` / 一次 `send` / 一次 `fire` / 一次 `interact`）：

- **同一步内**同一条诊断（码 + 消息 + 级别）只报一次。
- **装载期的静态诊断只报一次**，不在后续批次里重报——它们在每一批里都成立（例如某个未知属性），
  逐批重报会把诊断流淹成同一条消息，人就再也不看了。
- **批次产生的诊断不进入"已报过"集合**：同一个错误在**后续批次里再次出现必须再报**。
  抑制它会让"改了但还是错"看起来像"改成功了"——**那是比崩溃更糟的假成功**，
  而且它恰好发生在最需要诊断的时刻（驱动者正在循环重试）。
- 由程序状态**推导**出来的诊断（`validate` 那一族）在每一批都会重新计算：程序的当前状态
  是什么样，诊断就应当是什么样。

## 4. 码表

### 4.1 结构与地址

| 码 | 级别 | 触发 |
|---|---|---|
| `SYNTAX` | 错误 | 该行不符合语法（词法或语法错误），**该行未应用**，不影响本批其余行 |
| `ID_DUP` | 错误 | 地址已被占用 |
| `PARENT_MISSING` | 错误 | 父地址不存在 |
| `TARGET_MISSING` | 错误 | 目标不存在：`set` 的目标 / `move` 的被移节点与新父 / `listen` 的订阅目标 / 探针的目标 / **`fire` 的目标** |
| `ANCHOR_MISSING` | 错误 | `before` / `after` 锚点不存在 |
| `MOVE_CYCLE` | 错误 | `move` 造成自环或成环 |
| `DEL_MISSING` | 警告 | `del` 目标不存在 |
| `REF_MISSING` | 错误 | 引用类属性（`source` / `template` / `options`）指向的目标**不存在** |
| `REF_KIND` | 错误 | 引用类属性指向的目标**存在但类型不对**（如 `template` 指向普通节点） |
| `ASSET_REMOTE` | 错误 | 资源地址是远程地址或绝对路径（`src` 只允许资源目录内的相对路径） |
| `ASSET_MISSING` | 错误 | 资源文件不存在于资源目录（仅在调用方提供了资源根目录时校验） |
| `ROW_CONTEXT` | 错误 | 派发行内事件却无法确定行上下文（不在模板内 / 行序号越界 / 模板未绑定） |
| `TEMPLATE_UNUSED` | 警告 | 模板未被任何列表绑定 |

**"目标不存在"家族按后果分档，级别不是随手定的**：

| 后果 | 级别 | 例 |
|---|---|---|
| **完全无效**（命令没有任何效果，而写它的驱动者会以为成功了） | **错误** | `set` 目标不存在 |
| **结构破坏**（会造成程序不一致） | **错误** | `move` 的被移节点 / 新父不存在 |
| **引用断裂**（程序能装载，但该属性永远不会生效——静默的无效） | **错误** | `source` / `template` / `options` 指向不存在或类型不符的目标 |
| **幂等**（本来就没那东西，"确保删掉"是合法意图） | **警告** | `del` 目标不存在 |

**不要"顺手统一"这四种级别**：`del` 与 `set` 的差别是真实的——删一个不存在的东西是幂等的，而设一个不存在的东西是完全无效的。分档保存了这个差异；统一会抹掉它。

### 4.2 词汇

| 码 | 级别 | 触发 |
|---|---|---|
| `UNKNOWN_ATTR` | 警告 | 属性名不在词汇表中（带近似建议） |
| `UNKNOWN_TYPE` | 警告 | 节点类型不在词汇表中 |
| `UNKNOWN_ICON` | 警告 | 图标语义名未识别（带近似建议） |
| `UNKNOWN_EVENT` | 警告 | 事件名未识别 |
| `ATTR_ON_TYPE` | 警告 | 属性不适用于该节点类型 |
| `REF_ATTR_EXPR` | 错误 | 引用类属性写了表达式 |

### 4.3 状态与动效

| 码 | 级别 | 触发 |
|---|---|---|
| `STATE_LAYOUT_ATTR` | 警告 | `states` 中出现布局类属性 |
| `STATE_UNKNOWN_ATTR` | 警告 | `states` 中出现外观白名单之外的属性 |
| `DISABLED_HANDLER` | 警告 | 静态 `disabled=true` 的节点却绑定了交互处理器 |
| `ANIMATE_UNKNOWN` | 警告 | `animate` 中出现非语义可动画属性 |

### 4.4 绑定与表达式

| 码 | 级别 | 触发 |
|---|---|---|
| `BIND_CYCLE` | 错误 | 绑定图出现环（编译期） |
| `BIND_UNKNOWN_REF` | 错误 | 绑定的引用目标不存在 |
| `BIND_EVAL` | 错误 | 绑定的运行期求值失败（类型不符、除零、未知字段、函数错误） |
| `BIND_OVERRIDDEN` | 信息 | `set` / `upsert` 覆盖了一个已绑定属性，该绑定被解除 |
| `UPSERT_KEPT` | 警告 | `upsert` 命中**已存在**的地址：只更新**给定属性**，声明里的类型 / 父 / 锚与现状不同而被保留（要改类型用 `del`+`add`，要搬家用 `move`） |
| `WHEN_NOT_BOOL` | 错误 | `when` 守卫求值结果不是布尔 |
| `EXPR_TYPE` | 错误 | 表达式类型不符（不在白名单转换内的混用） |
| `EXPR_UNKNOWN_FUNC` | 错误 | 未知函数 |
| `EXPR_DIV_ZERO` | 错误 | 运行期除零 |

### 4.5 能力与槽

| 码 | 级别 | 触发 |
|---|---|---|
| `CALL_CONTRACT` | 错误 | 参数缺失 / 多余 / 类型不符 |
| `CALL_UNKNOWN` | 错误 | 目标函数不存在 |
| `CALL_RESULT` | 错误 | 返回值不可序列化或不符合声明结构 |
| `CAP_NO_DOC` | 错误 | 能力的说明文本（docstring）为空——**不予注册** |
| `CAP_DEPS_MISMATCH` | 警告 | 能力模块的依赖声明与实际 import 不一致（不迁移、不缺包） |
| `CAP_IMPORT` | 错误 | 能力模块加载失败（文件缺失或导入抛错） |
| `SLOT_TIMEOUT` | 错误 | 调用超时（观察为超时态） |
| `SLOT_STALE_DROPPED` | 信息 | 旧序号的调用结果到达后被丢弃 |
| `SLOT_CANCELLED` | 信息 | 进行中的调用被新调用取消 |

### 4.6 执行与持久化

| 码 | 级别 | 触发 |
|---|---|---|
| `CONVERGENCE_LIMIT` | 错误 | 处理器级联达到轮次上限（**可见**，带触发链快照） |
| `PERSIST_SCHEMA_DRIFT` | 警告 | 状态与程序声明不符（不迁移、不丢数据） |
| `STATE_REBUILT` | 信息 | 状态文件缺失或不可读，从默认值重建 |

### 4.7 观察与降级

| 码 | 级别 | 触发 |
|---|---|---|
| `OBSERVATION_DROPPED` | 警告 | 观察流发生事件丢失（必须带丢失区间） |
| `DEGRADED_FEATURE` | 信息 | 渲染器不支持某**能力声明之外**的控件 / 属性 / 动效 / 图标 / 几何 / 截图 / 用户动作投递，已明确降级。**必须**带 `feature` 字段（机读）：`geometry` / `snapshot` / `interaction` / `control:<类型>` / `attr:<名>` / `animation:<名>` / `icon:<名>` |

`control:<类型>` 只对**词汇表里的节点类型**（`04-vocabulary.md` 第 2 节）成立：`root` 是结构锚点、
不是词汇（`validate` 同样跳过它），把它算成"未声明支持"会在**每一个**程序上产生一条假降级。
`template` 则**在词汇表内**——声明支持它就表示"能展开模板行"，不展开才是降级。
| `PROBE_NO_CONSUMER` | 警告 | 探针动词在无驱动者连接时被使用。**由宿主发出**——只有宿主知道有没有消费者 |

**`DEGRADED_FEATURE` 与能力声明的闭环（声明即 oracle）**：能力声明（`05-render-contract.md`
第 1 节）说"我支持什么"，本码说"我没支持的我说了"。conformance（`conformance/README.md`
第 6 节）据此分档：声明支持却做不到、或未声明支持却静默，都不符合规范。降级的发生**不得**
取决于"有没有 LLM 在看"——信息级诊断进观察流，谁连上谁看到。

### 4.8 交互覆盖

| 码 | 级别 | 触发 |
|---|---|---|
| `UNCOVERED_INTERACTION` | 警告 | 控件的主交互事件（见 `04-vocabulary.md` 第 5.1 节）**既没有处理器、也没有被订阅**——没有任何人在看它，用户操作不会有任何反应 |
| `UNCOVERED_FAILURE` | 警告 | **处理器动作里**的 `call`（即用户触发的能力调用），其 `error` / `timeout` **既没有处理器、也没有被订阅**——调用失败时界面上不会有任何可感知的变化 |
| `BOUND_VALUE_NOT_WRITTEN` | 警告 | 控件的 `value` / `selected` 绑定了数据源，且它有 `change` 处理器，但那些处理器**没有回写该数据源**——用户改动会被绑定重算覆盖（界面弹回） |

## 5. 版本变更记录

### 2.1（相对 2.0，**兼容**）

只做**新增**，旧程序的可观察行为不变：

- **写回能力补齐**：程序 IR → 源文本的序列化（`program_source` / `program_lines`），与协议
  `dump` 请求配套；`conformance` 新增**往返用例**（命令批 → 写回 → 重载 → 行为等价）。
- **新增节点类型 `dialog`（模态对话框）**：铺满父的内容区、**可见时阻断下层交互**、后声明的在上；
  显隐复用运行期状态标志 `visible`（`visible=false` 即关闭）。配套两条**可断言的渲染契约**
  （见 `05-render-contract.md` 第 2、4 节）。**为什么必须有它**：模态的实质是"阻断下层交互"，
  而只靠 `visible` 手写覆盖层做不到——`visible` 不控制"能不能点"，点击会穿透，于是"删除前确认"失效。
  - 加节点类型属**兼容**类（不改变既有程序的语义）。但要注意：`controls` 声明为 `null`（= 支持全部标准）
    的实现现在**也声明了** `dialog`——若它做不到阻断，会因**声明即 oracle** 被判不符（这正是该机制的作用）。
    做不到就**如实声明子集**，未声明者走可见降级（`feature=control:dialog`）。
- **新增诊断**（均为新增，不改变既有程序的行为）：
  - `UNCOVERED_FAILURE`：处理器动作里的 `call`，其 `error` / `timeout` 既无处理器也未被订阅
    ——与 `UNCOVERED_INTERACTION` **同源**：判据都是"用户操作了，而界面上不会有任何可感知的变化"。
  - `REF_MISSING` / `REF_KIND`：引用类属性（`source` / `template` / `options`）指向的目标
    不存在 / 类型不符——**引用断裂**，属"静默的无效"。
  - `ASSET_REMOTE` / `ASSET_MISSING`：资源地址为远程或绝对路径 / 资源文件不存在。
- **新增可选装载参数** `assetsDir`：提供时校验 `src` 指向的文件确实存在；不提供则**跳过**
  ——语言实现不做无依据的判断。
- **澄清**：`TARGET_MISSING` 覆盖 `set` 目标 / `move` 的被移节点与新父 / `listen` 的订阅目标 /
  探针的目标（此前本条只写了 `set`）。
- **统一**：`image` 与 `avatar` 的资源失败可见性一致（此前只对 `avatar` 写了"兜底可见"）。
- **分档通则**：见第 4.1 节——"目标不存在"按后果分档（无效 / 结构破坏 / 引用断裂为**错误**，
  幂等为**警告**），**不得**顺手统一：`del` 与 `set` 的差别是真实的。
- **修正**：`DEGRADED_FEATURE(feature=control:…)` 只对**词汇表内的节点类型**成立——`root` 是
  结构锚点而非词汇（`validate` 早已跳过它），此前会被算成"未声明支持的控件"，导致**每一个**
  程序上都挂着一条假降级。诊断若不可信，整条观察流就会被训练成无人看（见第 4.7 节）。
- **修正**：命令批里 `data` 新声明的数据源按声明初值播种——此前只有装载期播种，
  运行期新声明的数据源**永远是空的**（而"先声明数据、再挂界面"是改写程序最常见的第一步）。
  配套用例 `cases/data.json`；`01-grammar.md` 第 7.6 节补一句"装载与命令批一视同仁"。
- **修正**：**生命周期边界上的作废要落在那一步**（见第 3 节与 `03-semantics.md` 第 4.3 节）。
  此前装载 / 重启作废在途调用后，它们的迟到结果仍会在**一段时间之后**产生一条
  `SLOT_STALE_DROPPED`——于是那条诊断漂进**无关的后续步骤**，让诊断失去归属。
  现在：作废在装载 / 重启那一步以 `SLOT_CANCELLED` 报出，迟到结果**不再产生诊断**。
  配套用例 `cases/capabilities.json` 的 `p-cap-inflight-cancelled-on-load`。
- **修正**：诊断作用域收窄为"一步"（见第 3 节）。此前批次产生的诊断也会进入"已报过"集合，
  于是**同一个错误在后续批次里被静默抑制**——  驱动者会以为改动成功了。补用例
  `cases/diagnostics.json` 三条（跨批重报 / 装载期静态诊断不重报 / 状态推导的诊断每批重算）。

### 2.1.2（相对 2.1.1，**兼容**）

只做**新增与补齐**，旧程序的可观察行为不变：

- **`upsert` 补齐实现**（此前**只被解析、从未被执行**：对已存在地址一律报 `ID_DUP`，
  而规范 01 第 7.3 节、03 第 2.7 节与 06 第 4.4 节的 `BIND_OVERRIDDEN` 都已把它当既定语义）。
  现在：不存在则新建（与 `add` 一致，含 `PARENT_MISSING` / `ANCHOR_MISSING`）；
  **存在则只更新给定属性**——未提及的属性与其绑定**原样保留**；命中的绑定给 `BIND_OVERRIDDEN`。
  类型 / 父 / 锚不是"给定属性"，声明与现状不同 → **警告** `UPSERT_KEPT`（新增码，见第 4.4 节）。
  配套用例 `cases/grammar.json` 四条（新建与幂等 / 更新 / 覆盖绑定 / 保留与形状可见）。
- **`fire` 不再静默**（第 3 节"没有静默"+ 第 3 节把 `fire` 列为"一步"）：目标**不存在** →
  **错误** `TARGET_MISSING`（分档通则：完全无效 → 错误；同族的 `interact` 早已这么报）；
  事件名未识别 → **警告** `UNKNOWN_EVENT`（与 `listen` 同一条规矩）。有诊断就不发布、不派发。
  "目标存在、但该事件没有处理器"**保持不报**：没人声明要响应它不是失败，且
  `UNCOVERED_INTERACTION` 已在编译期覆盖"声明了交互却没人接"的情形。
  配套用例 `cases/interaction.json` 两条。
- **引用类属性拒绝字段引用**：`source` / `template` / `options` 要的是**地址**（04 第 3 节）；
  写成 `source=#x.y` 这类**带字段的引用**（值引用）此前**跳过校验**——程序能装载，但该属性
  永不生效，属"引用断裂的静默无效"。现在报 **错误** `REF_KIND`。配套用例
  `cases/ref-targets.json` 一条。
- **澄清**：第 1 节"编译期诊断必须有行号 + 列号"与第 3.1 节"必须带行号（应该带列号）"自相矛盾；
  统一为"行号**必须**、列号**应该**"（与实现一致：目前只有语法错误的诊断带列号）。
- **澄清**：`05-render-contract.md` 不再引用词汇表中不存在的词（`ink` / `textarea`）；
  `03-semantics.md` 第 6 节点明"单驱动者连接"**由宿主在连接层保证**（语言实现没有连接概念）。

### 2.0（相对 1.x，**语义不兼容**）

程序的可观察行为发生改变，旧程序**不能**保证在新实现下表现一致：

- **值传播**：值类属性可直接写表达式并在渲染期持续求值；"`add` 静态字面量、`set` 求值"的分裂语义**废除**。
- **程序与状态分离**：运行期产生的值**不再**写回程序文本。
- **模板**：由语句改为节点类型，拥有独立地址与子节点；旧的"模板体内子节点"结构**不再存在**。
- **状态**：`hover` / `focus` / `pressed` / `error` 由"仅外观的字符串字段"改为**可读写的运行期属性**；状态外观统一收敛到 `states`。旧写法**不再被接受**。
- **控件**：`dropdown` 的选中值由 `value` 改为 `selected`。
- **动效与图标**：白名单改由**语义**定义，不再跟随任何后端的实现能力。
- **槽**：由三态（进行中 / 成功 / 失败）扩展为**五态**，新增**超时**与**取消**。
- **收敛**：绑定传播不再有轮次上限（DAG 拓扑序一次求值到位）；处理器级联的上限触发改为**可见错误** `CONVERGENCE_LIMIT`，取代旧的静默截断。
- **观察流**：队列压力下**不得**静默丢事件。
- **依赖**：能力依赖由"扫描源码 import"改为**显式声明 + 扫描兜底 + 不一致报警**。
- **插件**：取消"可改写下发的命令流"的钩子；标准语义不再可被插件改写。
- **`listen`**：不再有"某模式下无消费者则降级"的特殊规则。
- **注释记号**：`//` 取代 `#` + 空白（`#` 只作地址 / 颜色），两者彻底消歧。
- **渲染观测面**：几何快照（`observe.geometry`）与视觉快照（`snapshot`）成为一等的
  可选观测面；渲染器**必须**声明支持范围，未声明者被使用时产生 `DEGRADED_FEATURE`。
- **用户动作投递**：渲染器**必须**把用户动作转成事件；不能转必须可见降级
  （`feature=interaction`），**禁止**假装送达。
- **能力层**：新增 `CAP_NO_DOC` / `CAP_DEPS_MISMATCH` / `CAP_IMPORT`；参数契约补齐
  "多余参数"与"类型不符"的判定（此前只查缺失）。
- **诊断形状**：`DEGRADED_FEATURE` 必须带机读的 `feature` 字段。

### 2.x 兼容改动

新增可选属性、控件、事件、图标、内置函数、诊断码，均属兼容改动，提升修订号即可。
