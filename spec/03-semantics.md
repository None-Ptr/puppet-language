# 03 · 执行语义

## 1. 命令批的应用

- 一批命令 = 驱动者一次下发的一组语句。
- **逐条应用，错误不阻断**：一条语句失败**不**阻止后续语句；这就是"部分应用"。
- **必须收集全部诊断**，每条带**精确行号**与列位置。
- **程序写回在批次结束时一次性完成**。批中失败的程序变更**不写回**，但已成功应用的变更会被写回。
- 批结束时修订号 +1。
- 批内**禁止**静默跳过任何语句：每条语句要么应用、要么产生诊断。

## 2. 值传播（活绑定）

### 2.1 定义

**值类属性**（见 `01-grammar.md` 第 6 节）的值若为表达式，即构成绑定。绑定的求值时机为：

1. 初次渲染；
2. 其**引用集合**中的任何值发生变化之后。

**引用类属性禁止**绑定（校验期错误 `REF_ATTR_EXPR`，见 `06-diagnostics.md` 第 4.2 节）。

### 2.2 求值顺序

- 按**绑定图的拓扑序**求值。同一节点内属性之间的书写顺序**无意义**。
- 求值只读取程序 IR 与状态 IR 的当前值，不产生副作用。**禁止**在求值过程中写入状态。

### 2.3 收敛（可证明）

- 绑定图是 DAG（`02-ir.md` 第 4 节）→ 拓扑序存在且唯一 → **一次求值即可到达终态**。
- **禁止**"迭代若干轮后放弃"的实现方式。绑定传播不存在"轮次上限"这个概念。

### 2.4 循环

- 静态环 → **错误** `BIND_CYCLE`（编译/校验期）。程序**不得**进入运行期。
- 实现**禁止**用运行期深度计数来兜住循环依赖。

### 2.5 求值失败

- 求值失败（类型不符、除零、未知字段、函数错误）**必须**产生诊断（`BIND_EVAL`）**并**产生一条观察事件。
- 渲染表现：若该属性此前有成功的值，**可以**继续显示该值，但**必须**同时暴露错误标记（如错误态置位）；若无成功值，**必须**显示明确的不可用占位。
- **禁止**静默显示旧值、**禁止**静默显示空白、**禁止**显示表达式源码文本（这是旧规范的缺陷）。

### 2.6 模板行

- 模板按行实例化：每行独立求值一次，行绑定字段取自该行的数据项。
- 行的增删由数据源变化驱动；行内绑定的重算范围**应该**限于受影响的行。

### 2.7 `set` 与绑定的优先级

- `set` 作用于**已绑定**的属性 = **显式覆盖**：解除该属性的绑定，写入字面量，并且**必须**产生诊断 `BIND_OVERRIDDEN`。
- `upsert` 对**其提及**的属性同理；未提及的属性保持原有绑定。
- **禁止**"写入成功但被绑定覆盖、因而看不出效果"这种静默无效。

### 2.8 控件的交互值与绑定

- 若控件的 `value` / `selected` 是**绑定**（表达式），它就是**派生值**：**控件不保存用户输入**。
- 用户交互产生 `change` 事件，**载荷携带新值**（`{value: <新值>}`）；处理器的 `as <名>` 绑定到该载荷。
- 因此"受控控件"的标准写法是 **绑定读 + 处理器回写数据源**：

  ```puppet
  add #tpl checkbox #done value=t.done
  on #done change as e:
      update_where #todos as r set done=e.value where r.text == t.text
  ```

  处理器写回数据源 → 触发传播 → 绑定重算 → 界面随之更新。
- **若不回写**，绑定重算会把用户改动覆盖掉（控件弹回）。这是派生值的必然结果，**不是缺陷**；但它确实是"操作了却没有持久效果"，所以：
  - 被 `listen` 订阅时不算静默失败——外部驱动者看得到事件（载荷含新值），会自己下发命令；
  - **有处理器但没有回写**它绑定所读的数据源 → **警告** `BOUND_VALUE_NOT_WRITTEN`（见 `06-diagnostics.md` 第 4.8 节）；
  - 既没处理器也没被订阅 → **警告** `UNCOVERED_INTERACTION`（见 `04-vocabulary.md` 第 5.1 节）。
- **两个绑定是正交的**：事件载荷的名字来自处理器的 `as`，行记录的名字来自**模板声明的** `as`（`01-grammar.md` 第 8.1 节）。

## 3. 事件

### 3.1 事件来源

用户交互、数据源**既有内容**的变化、槽状态变化、订阅。

**数据源的声明与初始化不是"变化"**：`data … = …` 建立数据源、写入初值，**不得**触发 `on <数据源> change`。否则装载期就会跑一遍级联，级联上限之类的诊断会在应用尚未运行时就消耗掉。

### 3.2 一个变更的处理顺序

1. 应用状态变更（数据源、节点运行期状态、槽）；
2. 按拓扑序重算受影响的绑定；
3. 分派匹配的处理器（`on`）；
4. 处理器产生的新变更**重新从第 1 步开始**；
5. 推送观察事件给订阅者与驱动者。

### 3.3 处理器链必须有界（且上限可见）

- 绑定传播本身可证明收敛（第 2.3 节），**不需要**上限。
- 但**处理器可以写数据源**，从而再次触发 `change`，这类级联**无法静态证明收敛**。
- 因此实现**必须**为处理器级联设置一个轮次上限；**达到上限时必须是可见错误** `CONVERGENCE_LIMIT`（带触发链的快照），**禁止**静默停止传播。
- 旧规范在此处静默截断（跑到上限就不再传播、不报任何东西），**本规范禁止**该行为。

### 3.4 禁用与不可见

- 状态标志 `disabled=true` 的节点**不触发**交互事件。拦截必须在**引擎层**生效（不只是界面层），否则程序化派发会绕过它。
- 若节点的静态声明的 `disabled` 恒为真，却又绑定了交互处理器 → **警告** `DISABLED_HANDLER`。
- `visible=false` 的节点**不占位**、不接收用户交互。

### 3.5 事件名

- 事件名集合由 `04-vocabulary.md` 定义；未识别的事件名 → **警告** `UNKNOWN_EVENT`。

## 4. 能力与槽

### 4.1 调用契约

- 函数必须有**非空说明文本**（供驱动者发现）；为空 → **错误** `CAP_NO_DOC`，该能力**不予注册**。
- 契约从签名与类型提示提取：参数名、类型、是否必需、默认值、返回类型、是否异步。
- 参数缺失、多余、类型不符 → **失败**（`CALL_CONTRACT`），**禁止**静默补默认值。
- 返回值**必须**可序列化，且符合声明结构；否则 **失败**（`CALL_RESULT`）。
- 目标函数不存在 → **失败**（`CALL_UNKNOWN`）。**禁止**静默返回空值。
- **依赖必须显式声明 + 扫描兜底 + 不一致必须报警**：能力模块声明其依赖（如 `REQUIRES`），
  实现**必须**扫描源码实际 import 作为兜底；两者不一致 → **警告** `CAP_DEPS_MISMATCH`。
  仅靠扫描 import 是启发式的：动态 / 条件 import 会被静默漏掉，直到部署机上才缺包。
- 能力模块**加载失败**（文件缺失、导入抛错）→ **错误** `CAP_IMPORT`，**禁止**静默忽略；
  能力体是否安全不在本规范承诺范围内（`CAP_IMPORT` 是**功能性**要求：agent 不能瞎）。

### 4.2 槽状态（五态）

```
进行中 → 成功 | 失败 | 超时 | 取消
```

- **超时必须支持**。一次永不返回的调用若只停留在"进行中"，对驱动者等于**永久失明**；这是不可接受的。
- 超时的判定来源可以是调用处声明的时限，或实现的默认时限；**必须**在能力声明与诊断中可见。
- 取消：同一槽上的新调用**可以**取消进行中的旧调用；取消**必须**产生可见观察。

### 4.3 并发与陈旧结果

- 同一数据源上的多次调用**可以**并行。
- 每次调用递增槽序号；被取代的旧调用**作废**，其结果不再被采用。
- **作废必须可见，而且要在"作出决定的那一刻"报**：
  - 新调用取代旧调用 → 落在**那一步**（`SLOT_CANCELLED`，含槽地址）；
  - 装载（含写回后的重载）与重启 → 落在**装载 / 重启那一步**（同样是 `SLOT_CANCELLED`）——
    在途调用是**上一个生命周期**的事。
- **迟到结果不得再产生诊断**。它已经由上面那条报过了；再报一次只会让它漂进当时正在跑的
  **无关步骤**，让诊断**失去归属**——而归属是诊断可被行动的前提，一条不知道该算什么诊断
  等于没有诊断。（实现可保留一条兜底的 `SLOT_STALE_DROPPED`：序号对不上**且**没有任何作废
  记录时才用；它不该是常规路径。）

### 4.4 槽值的读取

- 槽是**程序可读的状态**：`#槽.status`、`#槽.value`（以及实现定义的错误/超时原因）。
- 因槽值是可读状态，**值类属性可以直接绑定它**——"三段式"（某人被触发时去改某处文本）退化为可选的写法，而非唯一写法。

### 4.5 能力体与安全

- 能力体是**宿主提供的工具**，本规范不约束它做什么，也**不承诺**任何隔离。
- 但"能力缺失、加载失败、超时、异常"**必须**表现为可见观察——这是功能性要求，不因安全议题出局而豁免。

## 5. 持久化

- `persist=true` 的数据源，其**数据项**进入状态文件的**持久分区**；其余数据项进入**瞬态分区**（进程内，可丢）。
- 状态文件**必须原子写**。
- **结构漂移**（状态里出现程序未声明的字段、或类型不符）：**不自动迁移**、**不删数据**，产生诊断 `PERSIST_SCHEMA_DRIFT`。
- 状态文件缺失或不可读：从程序声明的默认值重建，并产生信息级事件。**禁止**因此拒绝启动。

## 6. 观察流

- 观察流承载：诊断、**订阅事件**、**探针结果**、状态变更摘要、槽变化。
- **订阅事件**的载荷为 `{目标地址, 事件名}`，行内事件另带行序号；只有被 `listen` 订阅的 `(地址, 事件)` 才推送（见 `01-grammar.md` 第 7.8 节）。
- **不得静默丢弃**：
  - 队列满 → **必须**背压；无法背压时**必须**声明断连或**必须**推送一条"事件丢失"标记（含丢失区间）。
  - 旧规范在队列满时直接丢事件且不告知任何人，**本规范禁止**。

## 7. 单写者与生命周期

- **每个 app 实例**同一时刻只接受**一个**驱动者连接。第二个连接**必须**被拒绝，并明确告知原因。
- 修订号是**per-app** 的序列（见 `02-ir.md` 第 3 节）。
- 生命周期：**程序真源存在即"活着"**。驱动者断开或窗口关闭只表示"暂时无人驱动"，程序与状态都不因此丢失。
