# 05 · 渲染契约

## 1. 总则：本契约只描述**可观察行为**

- 本文件定义"用户能看到什么、能在什么条件下触发什么"，**不定义**任何后端的控件、属性或 API 映射。
- **禁止**在本文件中出现"某属性等价于某后端某类的某字段"这类写法。渲染器如何实现是渲染器的自由。
- 凡本文件**未定义**的（字体度量、像素级外观、滚动条样式、动画缓动的精确曲线）→ **实现自由**，但同一实现在等价输入下**必须**给出一致结果。
- 渲染器**必须**声明其支持范围：控件 / 属性 / 动效 / 图标四类**词汇能力**，外加**几何** / **截图** /
  **无 GUI 驱动**三项观测与驱动能力，以及**宿主指针语义**（`pointer`，见第 10 节）。声明**必须机读**
  （conformance 实现协议第 4.1.1 节的 `hello` 握手）：词汇能力为数组（`null` = 支持全部标准），
  观测能力为布尔，`pointer` 为 `"mouse"` 或 `"touch"`（缺省 `"mouse"`）。
- **任何缺失或不支持都必须产生可见降级**（`DEGRADED_FEATURE`，**必须**带 `feature` 字段指明被
  降级的特性），**禁止**渲染成空白、**禁止**静默忽略。
- **资源缺失同理**：`src` 指向的文件在渲染时不存在 → **兜底可见**（见 `04-vocabulary.md`
  第 3.4 节），不留白、不静默。`image` 与 `avatar` 走同一套规则。
- **声明即 oracle**：conformance 以声明决定每条渲染期望是硬断言、还是退化为要求可见降级——
  声明支持却做不到 = 不符；未声明支持却静默 = 不符。
- **渲染器读状态，但不消费观察流**：实现**必须**能读到当前渲染状态（值 / 状态标志 / 模板行 /
  数据）而**不取走**观察流——观察流的所有权在**驱动者**手里（`observe` 是"取走"语义）。
  渲染器若靠在渲染时 `observe()` 取状态，就会把驱动者的事件与诊断吃掉，而界面看起来一切正常：
  那正是最隐蔽的静默失败。语言实现据此提供只读的 `Engine.render_state()`。

## 2. 布局语义

- **子节点顺序**：容器按声明顺序排列子节点；锚点插入（`before` / `after`）改变的是这个顺序。
- **主轴与交叉轴**：
  - `col` 的主轴为纵向，`row` 的主轴为横向；
  - `gap` 定义**相邻子节点之间的间隔**；`justify` 定义子节点在主轴上的分布；`align` 定义在交叉轴上的对齐。
- **窗口布局**（派生决定，已确认）：`window` 的直接子节点按**纵向**流动，等价于一个隐式的 `col`
  （`gap` / `justify` / `align` 同样适用）。渲染器不必为 window 另造一套布局规则。
- **弹性**：`flex` 表示剩余空间的分配比例。未声明 `flex` 的节点按内容尺寸参与布局。
- **换行**：`wrap=true` 时，主轴放不下的子节点进入下一行 / 下一列。
- **滚动**：`scroll` 声明时，溢出内容可滚动；未声明时溢出**可以**被裁剪。
- **尺寸**：显式给出 `w` / `h` 即为固定尺寸；未给出即由内容决定。`flex` 与显式尺寸同时存在时，**应该**以 `flex` 分配为基础、显式尺寸为约束下限。
- **绝对定位**：给出 `x` / `y` 的节点不参与正常流动布局。
- **不占位**：`visible=false` 的节点**必须**从布局中移除（不留空位）。
- **覆盖层（`dialog`）**：**必须铺满父的内容区**，且**不参与兄弟的流动排布、不占流动位置**；
  其子节点在覆盖层内按纵向流动（同 `col`）。隐藏（`visible=false`）时**必须**不占位、不绘制、不阻断。
- **层叠顺序**：**后声明的兄弟绘制在上**。这条对所有兄弟节点成立；对 `dialog` 尤其要紧——
  它是"多个对话框叠加时，最上层是最后声明的那个可见者"的依据（见 `04-vocabulary.md` 第 2.1 节）。

## 3. 值呈现语义

- **文本**：超出可用空间时**应该**截断或以省略号收尾；`tooltip` 存在时**应该**提供完整内容的查看方式。
- **图标**：以单色字形呈现，颜色随 `fg`。
- **进度**：给出 `value` 时为确定进度；未给出时**必须**呈现为"正在进行"的不确定态（而不是空条）。
- **图片**：`fit` 定义图片与可用空间的关系；**加载失败必须可见**（占位或错误标记），**禁止**空白。
- **头像**：`src` / `initials` / `icon` 三选一；资源不可用时**必须**回退到下一个可用形式，全部不可用时**必须**显示可见占位。兜底内容在资源加载期间**应该**已经可见。
- **下拉选项**：`options` 指向的数据源为空时，**必须**呈现为"无可选项"的可见状态。

## 4. 交互语义

- **可交互节点**：`button`、`input`、`checkbox`、`switch`、`slider`、`dropdown`、`tabs`，以及**带交互处理器**的容器（处理器可以挂在任何地址上）。
- **模态阻断**：存在**可见的 `dialog`** 时，**命中测试必须限制在该 `dialog` 的子树内**——其子树之外的
  交互一律被阻断，**禁止**点击穿透到下层控件。有多个可见 `dialog` 时，只有**最上层**（最后声明的可见者）
  参与阻断。
- **为什么这条必须写进契约**：模态的实质是"**阻断下层交互**"，不是视觉效果。只靠 `visible` 手写覆盖层
  做不到——`visible` 只控制"画不画"，不控制"能不能点"，点击会**穿透**到下层；于是"删除前确认"会**失效**
  （用户想点"取消"，结果又触发了删除）。因此它必须是**可断言的行为**，不能留给渲染器自行决定。
- **未声明支持 `dialog` 的渲染器**走**可见降级**（`DEGRADED_FEATURE`，`feature=control:dialog`），
  不得静默忽略。
- **渲染器必须把用户动作转成对应事件**：用户在节点上的实际操作（点按、输入内容、勾选、切换）
  **必须**按下面的可观察定义产生事件。渲染器**禁止**把事件来源限制为"只有程序化调用"——
  否则外部驱动者无法分辨"用户真的点了"与"只是引擎内部调了一下"。
- **不能转必须可见降级**：渲染器无法投递某类用户动作时（如根本没有渲染层），
  **必须**在投递时产生 `DEGRADED_FEATURE(feature=interaction)` 并如实报告"未送达"，
  **禁止**假装已送达——"点了没反应"正是静默失败。
- **事件触发条件**（可观察定义）：
  - `click`：在节点范围内按下并释放；
  - `change`：值发生变化（输入内容改变、勾选改变、开关翻转、滑块移动、下拉选中改变）；
  - `submit`：输入框内确认动作；
  - `focus` / `blur`：该节点成为 / 不再是键盘输入目标。
- **禁用**：`disabled=true` 的节点**不响应**交互，且**必须**呈现为不可用外观。拦截**必须**在引擎层同时生效（见 `03-semantics.md` 第 3.4 节），不得只依赖界面层。
- **不可见**：`visible=false` 的节点不占位，因此不可能被交互。
- **`tooltip`**：指针悬停一段时间后呈现，内容为 `tooltip` 的值。
- **可点按反馈**：带交互处理器的容器，按下/悬停**应该**呈现可感知的反馈（是否提供由渲染器自述；不提供必须可见降级）。

## 5. 状态外观语义

### 5.1 状态来源

- `hover`：指针进入节点范围；`focus`：节点成为键盘目标；`pressed`：按住；`error`：由程序写入的运行期标志。
- 这四个状态是**运行期属性**，程序可以读取（`#id.hover`）与写入（`set #id error=true`）。

### 5.2 状态优先级（派生决定，已确认）

- **互斥组**：`hover` / `focus` / `pressed` 同时最多一个生效，优先级 **`pressed` > `focus` > `hover`**。
- **正交叠加**：`error` 与 `disabled` 不参与上面的互斥，可与互斥组中的状态同时存在。
- **生效顺序**：
  1. 节点的基础属性；
  2. 互斥组中优先级最高的那个状态的外观（若 `states` 中有声明）；
  3. `error` 的外观覆盖（若声明且 `error=true`）；
  4. `disabled=true` 时，整体呈现不可用外观（降亮或等价处理）。

### 5.3 约束

- `states` 中只允许外观属性（见 `04-vocabulary.md` 第 3.6 节）；布局属性与非白名单属性分别触发 `STATE_LAYOUT_ATTR` / `STATE_UNKNOWN_ATTR`。
- 状态外观**不触发事件**、**不改写程序**。

## 6. 动效语义

- `animate` 列出参与过渡的属性；这些属性在值变化时**应该**在 `duration` 毫秒内按 `curve` 过渡到新值。
- 未声明 `animate` → **不做过渡**，值立即改变。
- 状态外观的变化（如悬停变色）**可以**默认带过渡；若默认开启，**必须**在能力声明中说明。
- 渲染器不支持某属性动画时 → **必须**产生 `DEGRADED_FEATURE`，并立即改变该值（不得静默保持原值导致"看起来没反应"）。

## 7. 可观察性（最低要求）

渲染器**必须**让外部驱动者能够获得以下三类观察——这是"能观察"的定义，也是外部调度者唯一被保证的能力：

| 观察面 | 内容 |
|---|---|
| **事件流** | 诊断、状态变更摘要、槽状态、订阅事件（见 `03-semantics.md` 第 6 节） |
| **状态快照** | 数据项、节点运行期状态、槽状态、修订号 |
| **视觉快照** | 当前界面的图像表示（供驱动者自行决定是否用作自检）；**可选**能力 |
| **几何快照** | **可选**：各节点的矩形（见第 8 节）。不支持时**必须**在被询问（`where`）时可见降级 |

- **是否使用**视觉快照做自检，属驱动者的决定，**不是**渲染器的模式。能力不随"是否带 LLM"而出现或消失。
- 视觉快照**可以**按需产生，不必持续。
- 几何快照与视觉快照是**两条独立**的观测能力：各自声明、各自降级——有几何者仍**可以**没有截图，反之亦然。截图是**兜底**（人看 / 驱动者自行判断），几何是**断言**（机器可判定关系）；二者不互相替代。

## 8. 几何快照与关系断言词汇（可选观测）

几何快照是**可选**能力；一旦提供，外部驱动者即有权用以下**定性 / 相对**关系描述布局期望。
全部关系**不比较绝对坐标**——字号、DPI、窗口尺寸不同**不得**导致断言不可移植：

| 类别 | 关系 | 语义 |
|---|---|---|
| 方位 | `left_of` / `right_of` / `above` / `below` | a 整体在 b 的左 / 右 / 上 / 下（允许 `tol` 内的接触） |
| 包含 | `contains` / `inside` | a 的矩形完全罩住 / 被罩于 b（允许 `tol`） |
| 重叠 | `overlaps` / `disjoint` | 两矩形相交面积非零 / 不相交 |
| 对齐 | `aligned_x` / `aligned_y` | 左缘 / 上缘之差 ≤ `tol` |
| 对齐 | `aligned_center_x` / `aligned_center_y` | 中心之差 ≤ 2·`tol` |
| 尺寸 | `same_width` / `same_height` / `same_size` | 宽 / 高 / 两者之差 ≤ `tol` |
| 间距 | `gap_h` / `gap_v` | 相邻间隙 == `value` ± `tol` |
| 比例 | `width_ratio` / `height_ratio` | 宽 / 高之比 == `value` ± `tol`（比例容差缺省 0.05） |

- `tol` 为像素容差，缺省 **1**；间距 / 比例关系**必须**显式给 `value`。
- 坐标系：以**窗口内容区**左上角为原点，向右 / 向下为正，单位为**浮点像素**。
- 本节是**断言词汇**，不是布局系统的定义——布局语义仍以第 2 节为准；conformance 用例
  （`conformance/cases/render.json`）按本表编写。

## 9. 明确不定义的

字体族与度量、像素级抗锯齿与阴影质量、滚动条外观、缓动曲线的精确数学形式、窗口装饰、主题的具体配色表。

## 10. 触摸宿主（指针语义补全；2.1 修订，纯增量）

触摸宿主上，第 4 / 5 节的指针与键盘概念存在规范沉默。本节补全它们——**纯增量**：
缺省宿主 `pointer=mouse`，既有实现与既有用例的行为一字不变。

- **自述**：`hello.rendering.pointer` ∈ `{"mouse", "touch"}`，缺省 `"mouse"`。触摸宿主
  **必须**自述 `"touch"`——降级必须自述，这与几何 / 截图的自述是同一条原则。
- **T1（`hover` 降级）**：`pointer=touch` 时 `hover` 状态**永不激活**（触摸没有悬停）。
  程序读到 `#id.hover` 恒为 `false`；`states.hover` 的外观声明不生效——但这**不是**
  静默忽略，而是本条款定义的宿主语义（且宿主已通过 `pointer` 自述）。
- **T2（`focus` 规则）**：`pointer=touch` 时，可编辑控件（`input`）在
  **tap 时获得焦点、tap 其他处时失去**；不可编辑控件**不建立焦点**——`focus` 状态与
  `focus` / `blur` 事件只对可编辑控件有定义。
- **T3（`pressed` 窗口）**：`pointer=touch` 时 `pressed` 自 touch-down 起、至 touch-up
  或系统取消手势止。宿主平台使 `pressed` 不可感知时**可以**缩短该窗口，但**必须**在
  `hello.rendering.notes` 里如实说明（同 T1 的自述原则）。
- **T4（手势不扩）**：长按 / 滑动等触摸手势**不进**本版本的词汇表——它们是新的
  交互动词，会连带撑大 `on` 事件集与渲染器契约；等真实需求出现再立项。
- **conformance**：现有用例零改动（T1 是"永不激活"，没有任何既有用例因此变红）。
  `pointer` 值域由 runner 在握手时校验（值不合法 = 可见 FAIL）。
